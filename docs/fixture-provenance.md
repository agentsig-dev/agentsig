# Fixture provenance and reproducibility

## Scope

This dataset was prepared before any agentsig library implementation.
Expected signatures and canonical text were not generated by agentsig.
The original fixture commit contains source data, attribution, and an
independent integrity test.

RFC publications are identified here by RFC number, section, and source content
hash; no unrelated Git commit is presented as their identifier. Complete texts
retain their copyright notices. The project's MIT license does not relicense
these documents. Extracted code components retain the IETF Trust Revised BSD
notice. Corrections discovered through RFC errata review must be separately
sourced rather than silently applied to original fixtures.

### Applied transformations

- PEM and JWK: remove publication indentation only; append a final LF.
- Signature base: remove publication indentation and RFC 8792 presentation folds.
  Preserve significant whitespace before a fold; do not append a final LF.
- Signature headers: apply the same presentation transformation; no final LF.
- Signature bytes: decode the published base64 value without recomputing it.
- Example request head: an LF-delimited textual representation, not HTTP wire
  format; it contains neither CRLF nor the body.
- Original RFC texts: retain without transformation.

The B.2.6 signature base is 284 bytes and the signature is 64 bytes. These sizes
and their hashes expose accidental whitespace or trailing-newline changes.

**The published private key is not secret and must never be used in production.**
A fixture key must not become the default for automatic key generation.

JSON tests, schemas, upstream documentation, and the license were copied as
bytes directly from Git objects. Working-tree CRLF conversion in the clone does
not affect the import. Upstream generators and CI scripts were not executed.
The upstream copyright notice and three-clause BSD license remain unchanged.

The test loader must preserve the decimal/integer distinction in expected JSON
numbers. Converting everything to JavaScript numeric values can lose the expected
serialization of integer-valued decimals. This distinction must not be inferred
from the agentsig parser's output or by reparsing the serialization expectation.
Binary expectations use the upstream base32 representation; this is distinct
from the HTTP field's base64 syntax.

## Integrity and line endings

The [manifest](../tests/fixtures/manifest.json) records every imported file's
path, source, byte length, and SHA-256.

The [independent integrity test](../tests/fixture-integrity.test.mjs):

- Reads files as bytes and compares them with the manifest.
- Verifies the RFC signature with Node's built-in cryptography, without agentsig.
- Checks that CRLF conversion and an added final LF invalidate the signature.
- Performs real staging and checkout in isolated temporary Git repositories
  under three automatic line-ending settings, comparing index/worktree hashes.
- Does not change the user's global Git configuration.

[Git attributes](../.gitattributes) enforce LF for text fixtures and exempt binary
signature/key files from conversion. Because these settings do not automatically
repair an existing working tree, manifest checks are also needed before checkout.

The [fixture CI matrix](../.github/workflows/fixtures.yml) targets Node 20/22/24
on Windows/Linux. The user confirmed green CI for **core-m1** on September 18,
2026, and subsequently confirmed the **core-m2** CI/fixture workflows.
Those confirmations do not establish CI success for later local changes.

The [engine-independent audit](../scripts/audit-fixtures.mjs) checks the
RFC text → fixture → Node cryptography chain and verifies that the original
fixture commit contains no library implementation. It runs through the
audit:fixtures command in the [root manifest](../package.json) without dependency
installation or an engine build. The user originally added this script in
commit **5fd54d3**. English translation of comments and console diagnostics
must preserve its checks and all pinned fixture bytes.

The workflow has no path filter: every PR, including fixture changes, runs the
audit and integrity checks. Full Git history is fetched for the historical
commit check. The audit normalizes presentation for some text comparisons, so
manifest/integrity checks remain separately required for exact byte equality
and final-newline handling; the audit is not a substitute for them.

## Reimporting

The [import script](../scripts/import-fixtures.mjs) does not automatically
download sources. It checks previously downloaded RFC texts against their
hashes and a temporary upstream clone against the pinned commit, stopping on
mismatch. Source updates require an explicit fixture change, license review,
manifest diff, and independent integrity tests.

Never replace expected outputs with production implementation outputs merely
to make tests pass. The repository's English-language policy does not authorize
translation or normalization of immutable upstream sources, cryptographic
fixtures, or deliberate Unicode test inputs.
